# 训练智能闭环升级与验收

更新日期：2026-10-20

## 一、业务闭环与数据流

```text
周计划选择偏好动作
  → 训练后记录动作、组数、次数、重量、动作 RPE 和完成度
  → 恢复弹窗记录酸痛、睡眠、精神状态及疼痛信号
  → 后端先判定恢复安全边界
  → 无阻断信号时回溯同动作最近 2–3 次记录
  → 生成待处理进阶建议卡，用户采纳或忽略
  → 周回顾汇总完成率、平均 RPE、恢复、伤痛信号和动作进步
  → 生成下周计划预览
  → 用户确认后才写入下一周计划
```

旧训练日志继续显示；旧记录没有动作明细时明确显示“旧记录：未记录动作明细”，不会推断动作或恢复情况。

## 二、模块与文件清单

### 1. 数据模型与迁移

- `backend/app/models/training_intelligence.py`
  - `exercise_library`：动作库。
  - `training_exercise_entries`：每条训练日志的动作级明细。
  - `recovery_checkins`：训练后恢复打卡。
  - `exercise_advice`：动作进阶建议及采纳状态。
  - `plan_adjustments`：下周计划调整预览及确认状态。
- `backend/app/database.py`
  - 注册扩展模型、初始化种子数据。
  - `training_preferences` 新增 `preferred_exercise_ids`。
  - 新表加入账号数据归属与级联删除流程。
- `backend/migrations/20261020_training_intelligence.sql`
  - 可审阅、可手工执行的 PostgreSQL 建表 SQL。

应用启动时会通过 `create_all` 创建新表，并使用 `ALTER TABLE ... IF NOT EXISTS` 兼容已有数据库。正式部署仍建议按迁移 SQL 留存数据库变更记录。

### 2. 动作库

- `backend/app/services/exercise_library.py`
  - 24 个内置动作，覆盖胸、背、腿、肩、臂、核心。
  - 每个动作包含目标肌群、器械、姿势/呼吸/发力要领、常见错误与修正、退阶、进阶和替代动作。
  - `ensure_exercise_seed(db)` 可重复运行，不会重复插入。
- `backend/scripts/seed_exercises.py`
  - 独立种子脚本。
- `web/src/components/training/ExerciseLibrary.vue`
  - 搜索、部位筛选、动作选择。
- `web/src/components/training/ExerciseDetailDialog.vue`
  - 计划页与日志页共用的动作详情弹窗。

### 3. 渐进超负荷

- `backend/app/services/progressive_overload.py`
  - `progression_recommendation(records, experience, last_advice_date, warning_symptom)`。
  - 新手读取最近 2 次，其他等级读取最近 3 次。
  - 相同重量、次数达标、动作 RPE 不高于 8 才进入建议。
  - 双进阶顺序：先增加 1–2 次；到次数上限后加重 2.5%–5%，次数回到区间下限；自重动作无法小幅加重时加 1 组。
  - 每次只改重量、次数或组数中的一个变量。
  - 新手、进阶、资深的建议冷却期分别为 7、14、21 天。
  - 关节疼痛、锐痛、肿胀或恢复阻断时不生成建议。
- `web/src/components/training/ProgressionAdviceCard.vue`
  - 展示具体方案、依据记录和理由。
  - 支持采纳、忽略；状态持久化。

### 4. 恢复打卡

- `backend/app/services/recovery_service.py`
  - `assess_recovery(checkin, performance_declined)`。
  - 高酸痛、睡眠差、近期表现下降同时出现时标记恢复不足。
  - 生病时优先休息。
  - 关节疼痛、锐痛或肿胀返回停止相关动作的边界提示，不输出进阶建议。
  - `needs_deload(consecutive_training_weeks)` 在连续训练至少 4 周时允许触发减载判断。
- `web/src/components/training/RecoveryCheckinDialog.vue`
  - 训练保存前弹出恢复打卡。
- `web/src/components/training/RecoveryPanel.vue`
  - 展示今日和本周恢复水平。

所有提示都使用“记录提示、建议休息、寻求专业帮助”等表达，不进行医疗诊断。

### 5. 周计划自适应

- `backend/app/services/plan_adjustment_service.py`
  - `build_adjustment(plan, stats)` 只生成计划副本与解释，不修改原计划。
  - 高完成率且恢复良好：保持动作与训练日，允许按已采纳建议微调一个变量。
  - 完成率低或恢复不足：降低单次时长。
  - 连续 4 周且恢复或 RPE 偏高：生成减载周，动作不变，组数或强度约减半。
  - 有疼痛警示：不加量。
  - 停滞：建议同目标肌群变式，保留用户确认步骤。
- `web/src/components/training/PlanAdjustmentPreview.vue`
  - 显示“改了哪些、为什么改、哪些不变”。
  - 周日进入周回顾时自动生成预览；其他日期可手动生成。
  - 点击确认后才写入下周 `weekly_plans`；取消不写入。

## 三、关键接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/training/exercises` | 搜索和筛选动作库，参数 `q`、`muscle`、`equipment` |
| GET | `/api/training/exercises/{id}` | 读取动作详情 |
| POST | `/api/training/logs` | 保存整场日志、动作明细、恢复打卡并生成进阶建议 |
| GET | `/api/training/logs` | 读取详细日志、恢复状态和建议卡 |
| PUT | `/api/training/advice/{id}` | `adopted` 或 `ignored` |
| GET | `/api/training/recovery/summary` | 今日/本周恢复状态 |
| POST | `/api/training/adjustments/preview` | 按 `week_of` 生成待确认的下周预览 |
| PUT | `/api/training/adjustments/{id}` | 确认或取消预览；确认时写入下一周计划 |

原 `/api/log`、`/api/logs` 接口保留，已有调用和历史数据不受影响。

## 六、单测要点与已执行结果

测试文件：`backend/tests/test_training_intelligence.py`

- 两次相同重量、次数达标、RPE 7：生成加次数建议。
- 次数达到上限：生成加重建议并回到低次数。
- RPE 9、重量不一致：不生成建议。
- 关节疼痛：不生成建议。
- 高酸痛 + 睡眠差 + 表现下降：恢复不足。
- 连续 4 周：满足减载判断。
- 种子数量不少于 20 且覆盖六个部位。
- 接口连续记录两次后产生建议，可采纳。
- 下周预览生成后数据库没有下周计划；确认后才写入。

执行：

```powershell
python -m unittest backend.tests.test_training_intelligence -v
cd web
npm.cmd run build
```

当前结果：7 项后端测试通过；`vue-tsc --noEmit` 与 Vite 构建通过。

```powershell
cd "D:\杭电培训\项目\Agent—个性化健身运动规划业务\fitness-coach-agent\web"

```

浏览器打开 `http://127.0.0.1:8000`：

1. 登录，完成今日安全筛查。
2. 在“计划”中搜索动作、查看要领，选择偏好动作并生成计划。
3. 在“记录”中添加动作，填写组次、重量和动作 RPE。
4. 点击下一步，填写恢复状态并保存。
5. 对同一动作使用相同重量连续记录两次，次数达标且 RPE 不高于 8，检查进阶卡。
6. 对建议执行采纳或忽略，刷新后确认状态仍保留。
7. 记录关节疼痛、锐痛或肿胀，确认没有进阶卡，并显示停止相关动作与寻求专业帮助的提示。
8. 打开“回顾”，生成下周预览；在确认前检查下周计划未变化，确认后检查下周历史计划出现。

## 八、边界说明

- 体脂秤 API 未接入，本次升级只使用用户主动记录的训练和恢复数据。
- 建议是训练负荷管理辅助，不是医疗诊断或治疗方案。
- 动作替代保持目标肌群信息一致；实际替换仍由用户在动作库中确认。
- 缺失动作、恢复或 RPE 数据时不强行推断，规则会保持计划或提示补充记录。
